Créer sa propre commande

Cinq étapes. Aucun redémarrage, aucune compilation, aucun enregistrement nulle part.

  1. Créer le dossier

    mkdir -p ~/.claude/skills/<nom> pour une commande personnelle, disponible dans tous vos projets — ou .claude/skills/<nom> à la racine d'un dépôt pour une commande de projet, versionnée avec le code et partagée par l'équipe.

  2. Créer le fichier SKILL.md dedans

    Le nom du fichier est imposé, en majuscules. C'est le dossier qui donne son nom à la commande, pas le fichier.

  3. Ajouter le frontmatter YAML

    Entre deux lignes de trois tirets ---, en tête de fichier. Un seul champ est obligatoire : description. C'est lui que Claude lit pour décider si la commande est pertinente.

  4. Écrire les instructions en markdown en dessous

    Du texte, adressé à Claude. Écrivez-le comme une consigne à un collègue qui prend le dossier : ce qu'il doit faire, dans quel ordre, et ce qu'il ne doit pas faire.

  5. Sauvegarder

    La commande /<nom> est disponible immédiatement — la détection se fait à chaud.

~/.claude/skills/1/SKILL.md
---
description: Active un mode d'exécution strict.
disable-model-invocation: true
---

À partir de maintenant, pour le reste de la session :

1. Écoute exactement ce que l'utilisateur dit.
2. Fais exactement ce qu'il demande, rien de plus.
3. Ne sois pas verbeux — réponses minimales, consommation de tokens réduite au maximum.
4. En cas de doute, pose une question avant d'agir.
5. Ne décide jamais sur une hypothèse non validée par l'utilisateur.
Le champ disable-model-invocation: true de cet exemple est facultatif. Il empêche Claude de déclencher la commande de lui-même : elle ne part que si vous tapez /1. Utile pour tout ce qui change le comportement de la session plutôt que d'exécuter une tâche.
