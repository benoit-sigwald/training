Writing your own command

Five steps. No restart, no build, no registration anywhere.

  1. Create the folder

    mkdir -p ~/.claude/skills/<name> for a personal command, available across all your projects — or .claude/skills/<name> at the root of a repository for a project command, versioned with the code and shared by the team.

  2. Create the SKILL.md file inside it

    The filename is fixed, in capitals. It is the folder that names the command, not the file.

  3. Add the YAML frontmatter

    Between two lines of three dashes ---, at the top of the file. Only one field is required: description. That is what Claude reads to decide whether the command is relevant.

  4. Write the instructions in markdown below it

    Plain text, addressed to Claude. Write it the way you would brief a colleague picking up the job: what to do, in what order, and what not to do.

  5. Save

    The /<name> command is available immediately — detection happens live.

~/.claude/skills/1/SKILL.md
---
description: Turns on a strict execution mode.
disable-model-invocation: true
---

From now on, for the rest of the session:

1. Listen to exactly what the user says.
2. Do exactly what they ask, nothing more.
3. Do not be verbose — minimal answers, token use kept as low as possible.
4. When in doubt, ask a question before acting.
5. Never decide on an assumption the user has not confirmed.
The disable-model-invocation: true field in this example is optional. It stops Claude from firing the command on its own: it only runs when you type /1. Useful for anything that changes how the session behaves rather than performing a task.
